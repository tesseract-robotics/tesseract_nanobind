!!! note "Accepted deviation rules"
    - `algorithm-internal-namespace`: `time_parameterization::totg::{Path, PathSegment, PathData, Trajectory}` are the implementation classes of the bound `TimeOptimalTrajectoryGeneration`; Python reaches them through `compute`.
    - `boost-graph-property-tag`: Boost Graph property tags (`vertex_link_t`, …) select the properties `SceneGraph` stores; Python reaches the properties through `SceneGraph` methods.
    - `bound-in-other-module`: The class is bound in another extension module, which defines its Python type once for every module; its members are compared against that module's stub.
    - `byte-buffer`: A `(const uint8_t* bytes, size_t len)` pair is one Python `bytes` argument: the binding passes the buffer and its size (`createMeshFromBytes`, `BytesResource`).
    - `clock-deadline`: `TaskComposerFuture.waitUntil` takes a `std::chrono::high_resolution_clock` time point, which is `steady_clock` under libc++ and MSVC and has no epoch Python can name; `waitFor(duration)` is its Python form.
    - `clone-as-copy`: `__copy__`/`__deepcopy__` bind the C++ copy constructor and return the concrete type; `clone()`, which returns the `unique_ptr<…Interface>` of the type erasure, is then covered by `__deepcopy__`.
    - `container-protocol`: `size()` is bound as `__len__`, `operator[]` as `__getitem__`/`__setitem__` and `erase` (one element, or a range) as `__delitem__` (of an index, or a slice), the Python container protocol.
    - `context-from-data-storage`: `TaskComposerExecutor.run(node, data_storage, dotgraph=False, name='run')` builds the `TaskComposerContext` that the C++ `run(node, context)` takes, the shape of upstream's `TaskComposerServer::run(node, data_storage, dotgraph, executor_name)`.
    - `copied-vector-field-mutator`: A `std::vector` field converts to a fresh Python list on each access, so `obj.field.append(x)` edits a copy; `add…`/`clear…` methods mutate the C++ vector.
    - `declared-never-defined`: Declared in the header, but the 0.35.0 library defines no such symbol (`nm` finds none in its library): a binding cannot link it. `JointGroupInstructionInfo::getWorkingFrame` (`libtesseract_motion_planners_simple`; its value is the bound `working_frame_transform`) and `validateSeedStructure` (`libtesseract_command_language`).
    - `derived-element-container`: An overload taking a container of a derived class only upcasts into its base-element sibling (`CompoundMesh(vector<ConvexMesh>)` → `CompoundMesh(vector<PolygonMesh>)`, compound_mesh.cpp:59-63); Python passes a list of any subclass to the bound base-element overload.
    - `dot-dump-hook`: `TaskComposerNode::dump(std::ostream&, …)` and its overrides are the virtual hook behind `getDotgraph`/`saveDotgraph`, which return or write the same DOT text.
    - `eigen-default-precision`: `EIGEN_DEFAULT_PREC` re-exports `Eigen::NumTraits<double>::dummy_precision()` (1e-12) so Python compares with Eigen's own default tolerance instead of a duplicated literal.
    - `eigen-template-instance`: `Eigen::Hyperplane<double, 3>` and `Eigen::ParametrizedLine<double, 3>` have no Eigen typedef; the class takes Eigen's own `…3d` naming (`Vector3d`, `Quaterniond`).
    - `eigen-value-wrapper`: `descartes_light::State` wraps one Eigen vector, `values`; its indexing, call, arithmetic, comma-initializer and conversion operators forward to it, and Python does the same on the bound `values` array.
    - `free-function-as-method`: A free predicate whose only parameter is `const T&` is bound as a method of `T` (`isWaitInstruction(const InstructionPoly&)` → `InstructionPoly.isWaitInstruction()`), beside `T`'s member predicates of the same shape (`isMoveInstruction`); a free binary operator on two `const T&` is bound as `T`'s dunder (`operator==(const OSQPSettings&, const OSQPSettings&)` → `OSQPSettings.__eq__`).
    - `hook-override-guard`: `__init_subclass__` on a concrete profile is installed by the package `__init__.py` (`refuse_hook_overrides`): the profile has no trampoline, so a Python subclass that overrides a hook the planner would never call is refused at class definition. A Python class-creation hook, with no C++ counterpart.
    - `ifopt-problem-only`: An overload taking `trajopt_ifopt::Problem` serves the `IfoptQPProblem` path, which is not Python API (`trajopt_sqp/ifopt_qp_problem.h` is unaudited); `TrajOptQPProblem` is the bound problem.
    - `iterator-pair`: A `begin()`/`end()` pair (and `cbegin`/`cend`) is bound as `__iter__`.
    - `k-prefix-enumerator`: trajopt's `kCamelCase` enumerators are bound in `UPPER_SNAKE` without the `k` (`kLowerBound` → `LOWER_BOUND`, `kQPSolveFailed` → `QP_SOLVE_FAILED`), the Python enum convention every tesseract enum follows; an enumerator bound under any other name stays a gap and a deviation.
    - `module-getattr`: A package `__init__.py` defines a PEP 562 module `__getattr__` to re-export a name lazily (an eager import would be an import cycle); it is an attribute-lookup hook, not API.
    - `nodes-variables-factory`: `createNodesVariables` builds a `NodesVariables` of one vector `Var` per waypoint in one call, the layout every `TrajOptQPProblem` example uses; the C++ constructor takes `std::vector<std::unique_ptr<Node>>`, which this factory fills.
    - `out-param`: A non-const lvalue-reference out-param (or a by-value `Eigen::Ref` of a non-const matrix) is returned in a tuple with the result (Phase A precedent: checkTrajectory), or alone when the C++ returns `void`.
    - `plugin-author-factory-interface`: An abstract `…Factory` whose pure virtual `create(…)` takes a `YAML::Node` is the interface a C++ plugin library implements; Python creates objects through the owning plugin factory (`TaskComposerPluginFactory`, `KinematicsPluginFactory`, `ContactManagersPluginFactory`) and cannot implement a plugin.
    - `plugin-config-ctor`: A `(…, const YAML::Node& config)` constructor that only the plugin factory calls (`TaskComposerExecutorFactoryImpl<T>::create(name, config)` and `TaskComposerTaskFactory<T>::create(name, config, plugin_factory)` pass the plugin's config block) has no Python caller; Python constructs the class from its other constructors or gets it from `TaskComposerPluginFactory.createTaskComposerExecutor` or `createTaskComposerNode`.
    - `poly-alternative-overloads`: A parameter typed as a type-erased Poly (`InstructionPoly`, `WaypointPoly`) is also bound once per alternative the Poly wraps (`push_back(MoveInstructionPoly)`, `MoveInstruction(CartesianWaypointPoly, …)`), so the stub names the types a caller passes; C++ converts each alternative through the Poly's converting constructor.
    - `presentation-dunder`: `__repr__` and `__str__` are Python presentation and need no C++ counterpart.
    - `profile-key-template`: `ProfileDictionary::getProfile<ProfileType>(ns, name, default)` derives the profile key from its template argument; Python passes the key to the bound `getProfile(key, ns, name)` (`profile.getKey()`, or `ProfileType.createKey()` once bound), which returns the registered profile class, and checks `hasProfile` for the default.
    - `python-hook-method`: Upstream's `…Python` method, documented "only available for python bindings" (`TaskComposerGraph::addNodePython`, `TaskComposerServer::addTaskPython`), is bound under the plain name (`addNode`, `addTask`); the `std::unique_ptr` overload it stands beside has no Python form.
    - `quaternion-rpy`: `Quaterniond.from_rpy`/`to_rpy` convert roll-pitch-yaw in the ROS/tf2 convention, which Eigen spells as three composed `AngleAxisd` rotations; `to_rpy` returns tf2's canonical ranges, which `eulerAngles` does not guarantee.
    - `reason-out-param`: `MotionPlanner::checkRequest(request, std::string& reason)` is bound as `checkRequestReason(request) -> str` (empty for a valid request) beside the bound `checkRequest(request) -> bool`: an `out-param` tuple would make `if checkRequest(req):` pass an invalid request, since a non-empty tuple is truthy (decision C2).
    - `reference-setter`: C++ assigns through a getter that returns a non-const reference (`getWaypoint() = wp`); Python cannot assign to a returned reference, so a `set…` method assigns through it.
    - `reference-wrapper-out-param`: `ContactResultMap.flattenWrapperResults` fills a `std::vector<std::reference_wrapper<ContactResult>>` with references into the map, which have no Python form; `flattenCopyResults` and `flattenMoveResults` return the same results (phaseB won't fix, C12).
    - `reference-wrapper-view`: An overload taking `std::vector<std::reference_wrapper<T>>` views objects owned elsewhere; Python passes the owner to a bound sibling overload, which builds the same view (`InstructionsTrajectory(program)`). Accepted only when a sibling overload is covered.
    - `scalar-last-quaternion`: Quaterniond takes (x, y, z, w), the project-wide scalar-last order; Eigen's constructor is (w, x, y, z).
    - `serialization-default-ctor`: The default constructor of a class that cereal serializes (it befriends cereal `serialize`, or its library's `cereal_serialization.h` declares a free one) and that declares another public constructor exists for deserialization only.
    - `sized-double-array`: `QPProblem::setVariables(const double* x)` reads `getNumNLPVars()` doubles through the pointer, with no length parameter; Python passes one float array, which the binding checks against `getNumNLPVars()` (`VariablesSizeError`) before passing its data.
    - `solver-behind-profile`: The classic-TrajOpt optimizer (`sco::Optimizer`, `BasicTrustRegionSQP`, `BasicTrustRegionSQPMultiThreaded`, `OptResults`, `BasicTrustRegionSQPResults`, `OptStatus`, `toString(OptStatus)`) shares `trajopt_sco/optimizers.hpp` with the bound `BasicTrustRegionSQPParameters`; `TrajOptMotionPlanner.solve` runs it, and Python sets its parameters through `TrajOptSolverProfile.opt_params`.
    - `split-var-pair`: `ContinuousCollisionConstraint`, `ContinuousCollisionConstraintD` and `ContinuousCollisionNumericalConstraint` take `std::array<std::shared_ptr<const Var>, 2> position_vars`; Python passes the pair as two named parameters, `position_var0` and `position_var1`, and the required `vars0_fixed`/`vars1_fixed` default to `False` (Python's `fixed0`/`fixed1`).
    - `std-library-enum`: The enum is declared by the C++ standard library, not an audited header; it is bound because a bound member returns it (`std::future_status` → `FutureStatus`, returned by `TaskComposerFuture.waitFor`).
    - `stdout-printer`: `Component.print(index, tolerance)` writes a table to `std::cout`, which bypasses `sys.stdout`; Python reads the same values through the bound `getValues` and `getBounds`.
    - `stream-insertion`: A free `operator<<(std::ostream&, const T&)` is bound as `T.__str__` (`T` a class or an enum); the virtual `print(std::ostream&)` such an operator writes through (descartes_light's `WaypointSampler`) is covered by the same `__str__`.
    - `stringstream`: A `std::stringstream&` parameter the C++ writes into is returned as `str`.
    - `template-instance-name`: Python cannot spell a C++ template argument, so each instance of a function template gets its own function named after the type (`createMeshFromPath<ConvexMesh>` → `createConvexMeshFromPath`, `Serialization::toArchiveStringXML<Environment>` → `environment_to_xml`); for a library's generic class name, the library prefix plus the instance suffix (`descartes_light::State<double>` → `DescartesStateD`), because the generic name says nothing about the library it comes from.
    - `third-party-global`: A module function wraps a process-global of a linked third-party library (`RNG_setSeed`/`RNG_getSeed` call `ompl::RNG::setSeed`/`getSeed`); no owned header declares it, and Python needs it for reproducible planning (#103, #109).
    - `to-string-as-str`: A `toString() const` returning `std::string` is bound as `__str__` (`TaskComposerNodePorts`).
    - `type-erased-data`: `PlannerRequest.data` and `PlannerResponse.data` are `std::shared_ptr<void>`: a planner's internal problem, type-erased; Python has no type to convert `void` to or from.
    - `type-erasure-interface`: The abstract `…Interface` of a type-erased `…Poly` is its C++ extension point (pure virtuals, a protected `equals`, cereal registration); Python holds the concrete classes and their Polys, and reaches the stored object through the bound casts (`InstructionPoly.as…`, and the waypoint casts), not through the accessor that returns the interface by reference.
    - `type-index`: `getType()` returns a `std::type_index`, which has no Python form; the bound `is…()` predicates and `as…()` casts answer the same question by name, and `AnyPoly.getTypeName()` returns the demangled type name.
    - `unbound-dependency-type`: A parameter, return or field typed by a library no module binds (`OsqpEigen::Settings`, `ompl::base::SpaceInformationPtr`), or by a type declared only in a header this report lists as not API (`trajopt::TermInfo`, `sco::ModelConfig`), has no Python form; the owning object exposes what Python needs instead: bound fields, or `set…` forwarders such as `OSQPEigenSolver`'s into its OSQP settings (`setPolish`, `setWarmStart(bool)`, `setMaxIteration`, …).
    - `unimplemented-observer`: `NodesObserver` has no implementation in trajopt 0.35.0 (the library exports only its base constructor), so `NodesVariables.addObserver` has nothing to register.
    - `upstream-broken-default`: A trailing defaulted parameter that upstream rejects for every non-default value stays unbound until upstream fixes it: `OFKTStateSolver(scene_graph, prefix)` throws for any non-empty prefix (tesseract-robotics/tesseract#1384).
    - `value-equality-unhashable`: `__hash__ = None` next to a bound `__eq__` makes a mutable value type unhashable, as Python does for any class that defines `__eq__`; it needs no C++ counterpart.
    - `vector-forwarding-no-python-form`: A class that forwards the `std::vector` interface leaves `data()` (raw pointer), `emplace`/`emplace_back` (perfect-forwarding templates), the iterator-range `insert(pos, first, last)` template, `swap(std::vector&)` and the reverse iterators unbound: Python builds the element and passes it to `push_back`/`insert`, and `reversed()` walks any sequence with `__len__` and `__getitem__`.
    - `yaml-node`: An overload taking a `YAML::Node` has no Python form (no Python type converts to one). It is accepted when a bound sibling overload of the same symbol takes a config file path or YAML text in that position and loads the same config, or the class binds a static `from_yaml(text: str)` that parses the text and calls this constructor (supplying a default `ProfilePluginFactory` where the constructor takes one).

!!! warning "Limitations"
    Python member names are checked against every declaration in the TU, so a Python-only member that shares a common C++ name (`size`, `clear`) is not flagged. Overloads are matched by arity and parameter type: each C++ parameter type and each stub annotation map to a key (`scripts/audit_types.py`), and a bound overload covers a C++ one only where the keys agree. A type the mapping does not know (a template parameter, `object`, a quoted C++ name) leaves that position to arity alone; the `type fallbacks` column counts the C++ overloads covered that way. Overloads that differ only in `const` of `this` or `&`/`&&` of a parameter count as one. A C++ overload with trailing defaulted parameters is covered only if a covering Python overload accepts all of them; otherwise the gap names the unreachable ones. An overload taking a raw buffer (a pointer to a non-`char` scalar) has no Python form and is reported whatever the arity, unless it is a `(const uint8_t*, size_t)` pair bound as one `bytes` parameter. A header the binding never includes that does not compile on its own is listed as `unparseable header`, at its first error, and its API is not checked.
